# Crates whose `#[ignore]`-gated (database-backed) suite runs in CI.
#
# `cargo test` skips these suites by design, so they only execute when CI
# explicitly opts a crate in here and provides a Postgres database. This is
# an **allowlist, not a denylist**, on purpose: a crate is added once its
# `--ignored` suite has been observed green, so CI starts green and stays
# meaningful. A denylist would have made the first CI run red and trained
# everyone to ignore it.
#
# The DB-gated suites are where the compliance controls are actually
# proven — a unit test cannot show that an audit digest survives a Postgres
# JSONB round-trip, or that a raw-SQL row edit is detected. Running them is
# the point of giving CI a database at all.
#
# Format: one crate path per line (as printed by `scripts/ci-crates.sh`).
# Blank lines and `#` comments ignored.

# person and worker were enrolled on 2026-07-26, once the pre-existing
# defects that had kept them out were fixed. For the record, what was
# actually wrong — none of it was in the compliance work:
#
#   * Both crates' `add_indexes_and_triggers` migration created the
#     `pg_trgm` extension *after* the indexes that use `gin_trgm_ops`, and
#     applied that operator class to a `text[]` column, which it does not
#     accept. The block could never apply, so on worker the whole migration
#     chain stopped there and `audit_log.seq` / `workers.worker_type` never
#     existed.
#   * person's rename-to-`person` migration renamed the tables but not
#     their `patient_id` foreign-key columns, which the SeaORM entities
#     declare as `person_id`.
#   * person's bulk-import advisory-lock key embedded a literal NUL as a
#     field separator. Postgres `text` cannot hold one, so every
#     identifier-keyed import row failed with `invalid byte sequence for
#     encoding "UTF8": 0x00`.
#   * Both crates' `tests/common/mod.rs` opened a Tantivy index at a path
#     no fixture created, so every integration test panicked before its
#     first assertion.
#   * worker's `Worker` and `HumanName` had lost the `#[serde(default)]`
#     attributes that person still had, so omitting an optional field —
#     `prefix`, `identifiers`, … — was a `422`.
