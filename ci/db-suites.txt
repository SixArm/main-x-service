# Crates whose `#[ignore]`-gated (database-backed) suite runs in CI.
#
# `cargo test` skips these suites by design, so they only execute when CI
# explicitly opts a crate in here and provides a Postgres database. This is
# an **allowlist, not a denylist**, on purpose: a crate is added once its
# `--ignored` suite has been observed green, so CI starts green and stays
# meaningful. A denylist would have made the first CI run red and trained
# everyone to ignore it.
#
# The DB-gated suites are where the compliance controls are actually
# proven — a unit test cannot show that an audit digest survives a Postgres
# JSONB round-trip, or that a raw-SQL row edit is detected. Running them is
# the point of giving CI a database at all.
#
# Format: one crate path per line (as printed by `scripts/ci-crates.sh`).
# Blank lines and `#` comments ignored.
#
# To observe a crate green before enrolling it, start its containerised
# Postgres and force the stage past this allowlist:
#
#   scripts/test-db.sh up <crate>
#   DB_SUITES_FORCE=1 scripts/ci-check.sh test-db <crate>
#   scripts/test-db.sh down <crate>
#
# `DB_SUITES_FORCE` is a local affordance only — setting it in CI would
# defeat the reason this file exists.
#

# authentication was enrolled on 2026-08-01, once its suite ran for the
# first time (38 tests, green vs Postgres 18). It had never been run
# against a database, and it was red for three unrelated reasons — a seed
# fixture missing the ABAC `attributes` column, two tests reading a
# magic-link token that SEC-A9 now stores hashed, and one asserting the
# decommissioned JWKS endpoint. It also hid a **production** defect: every
# `LOWER(email)` lookup emitted a MySQL `?` placeholder, so signup and
# magic-link sign-in failed against Postgres outright. That is the case
# for running these suites: a crate whose DB-gated tests never run is a
# crate whose database behaviour is unknown, not one that works.
#
# organization was enrolled on 2026-07-31, alongside its move from the
# Postgres `ILIKE` name search to Tantivy (tasks.md S-1). Its 22 DB-gated
# tests were observed green against a freshly created Postgres 18
# database — a fresh DB specifically, because the suite's earlier passes
# had leftover rows from previous runs, and one of the new tests was
# found to be passing on a race rather than on the code under test. The
# search behaviour is exactly the kind that only a database can prove:
# that an index hit resolves to a live row, that a soft-deleted record
# leaves the index, and that `search_reindex` rebuilds from the table
# alone.
#
# content-management-system was enrolled on 2026-07-30, with its first
# code round (CMS-T1-T4): 6 request tests + 1 enforcement binary observed
# green against Postgres 18 locally before being added here, per the
# allowlist rule above. Its DB-gated suite is where the declaration
# layer's real guarantees are proven — that a key clash is a 409 rather
# than a second site, that a delete refuses while children exist, that a
# visibility flip writes its own audit action, and that an unconfirmed
# breaking schema edit is refused.
#
# person and worker were enrolled on 2026-07-26, once the pre-existing
# defects that had kept them out were fixed. For the record, what was
# actually wrong — none of it was in the compliance work:
#
#   * Both crates' `add_indexes_and_triggers` migration created the
#     `pg_trgm` extension *after* the indexes that use `gin_trgm_ops`, and
#     applied that operator class to a `text[]` column, which it does not
#     accept. The block could never apply, so on worker the whole migration
#     chain stopped there and `audit_log.seq` / `workers.worker_type` never
#     existed.
#   * person's rename-to-`person` migration renamed the tables but not
#     their `patient_id` foreign-key columns, which the SeaORM entities
#     declare as `person_id`.
#   * person's bulk-import advisory-lock key embedded a literal NUL as a
#     field separator. Postgres `text` cannot hold one, so every
#     identifier-keyed import row failed with `invalid byte sequence for
#     encoding "UTF8": 0x00`.
#   * Both crates' `tests/common/mod.rs` opened a Tantivy index at a path
#     no fixture created, so every integration test panicked before its
#     first assertion.
#   * worker's `Worker` and `HumanName` had lost the `#[serde(default)]`
#     attributes that person still had, so omitting an optional field —
#     `prefix`, `identifiers`, … — was a `422`.
