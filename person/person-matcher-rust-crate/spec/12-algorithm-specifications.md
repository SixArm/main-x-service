## 12. Algorithm Specifications

Full per-component score tables and pseudocode are in [agents/matching-algorithm.md](../agents/matching-algorithm.md) under "Detailed Algorithm Specifications". Summary:

- **§12.1 Deterministic** — fires on same-scheme identifier agreement (any of 42 schemes), passport-book agreement, or full demographic-tuple agreement (normalised given + family + DOB + compatible gender).
- **§12.2 Component scoring** — per-field scores in `[0.0, 1.0]` or `None`. Identifiers: exact canonical equality. Names: `name_algorithm` (JW / Lev / Exact / Combined) with nickname boost to `≥ 0.9` and `0.95 × given + 0.05 × middle` blend. DOB: exact (`1.0`) or same-year day/month transposition (`0.5`). Gender / blood type / multiple birth: exact equality. Birth/death place: shared `score_named_place` (`0.7 × city + 0.3 × country`). Death date: reuses DOB transposition. Address: §12.4. Phone: E.164 preferred + legacy fallback. Email: canonical equality. Phonetic: Soundex. Relationships score as typed-set **Jaccard** over `(relation, person_id)` pairs (`|A ∩ B| / |A ∪ B|`), so a parent reference only agrees with a parent reference to the **same** person; tags score as set **Jaccard** over the case-insensitively normalised tag sets (`|A ∩ B| / |A ∪ B|`). Both are `None` (does not participate) when either side is empty (§23 T-33/T-34).
- **§12.3 Probabilistic** — `score = Σ(score × weight) / Σ(weight)` over participating fields. Phonetic bonus is asymmetric (`+ s × 0.05` when `s > 0.9`); only lifts.
- **§12.4 Address sub-score** — weighted average over postcode (0.5), city (0.3), line 1 (0.2). Line 1 is a `(house_number, street)` blend: `0.6 × street_sim + 0.4 × house_score` when both have a house number, street similarity alone otherwise. Empty-address fallback `0.5`. Best-of across `(current ∪ previous_addresses)` on both sides (FR-48).
- **§12.4a/b/c Place / date-of-death sub-scores** — see AGENTS for city / country blend rules.
- **§12.5 Confidence bands** — `score ≥ 0.90 → High`, `≥ 0.75 → Medium`, else `Low`; independent of `match_threshold`.
- **§12.6 Batch** — `match_one_to_many` (parallel-to-slice); `rank_one_to_many` (sorted descending; deterministic index tie-break). Engine is `Send + Sync`; consumers layer parallelism.
- **§12.7 Match evidence** — every `MatchResult` carries `evidence: Evidence` beside `score`, per the family contract [`agents/share/match-evidence.md`](../../../agents/share/match-evidence.md) (Fellegi–Sunter log-likelihood weights). `score`, `is_match` and `confidence` are unchanged by it. Code: `src/evidence.rs`.
  - **Weight.** Each non-identifier component that is `Some` adds `component_bits(s, m, u)`: `log2(m/u)` at `s ≥ 0.95`, `log2((1−m)/(1−u))` at `s ≤ 0.60`, linear between. A `None` component adds `0` and is not counted in `fields_compared`.
  - **`m`/`u` table** (informed estimates, not measurements): given name `0.95/0.01`; family name `0.92/0.005`; DOB `0.97/1e-4`; gender `0.98/0.5`; blood type `0.99/0.25`; multiple birth `0.98/0.5`; address `0.70/1e-4`; birth place `0.90/0.01`; death date `0.95/1e-4`; death place `0.90/0.01`; phone `0.60/1e-3`; email `0.70/1e-4`; relationships `0.60/0.10`; tags `0.50/0.20`. The phonetic bonus (`0.95/0.60`) is, as in §12.3, agreement-only (when `> 0.9`), because it is derived from the name components.
  - **Identifiers** count as one field. A shared value under any of the 42 national schemes, or a shared passport `(country, number)` pair — the §12.1 identifier rules — adds `IDENTIFIER_BITS = log2(0.99/1e-12) ≈ 39.85` once. The §12.1 demographic tuple is **not** an identifier and adds no identifier bits.
  - **Contradictions.** Each national scheme under which both records parse a value (the scheme's own parser is the normalisation, so blank/invalid values are ignored) and the values differ is a `Contradiction { field: "identifier:<scheme>" }` (scheme = the `Person` field name, e.g. `identifier:us_ssn`) and adds `log2(0.01/(1−1e-12)) ≈ −6.64`. **Passports never contradict**: a passport number names a document, and a renewed book legitimately carries a new number.
  - **Strength**, checked in order: any contradiction → `Contradicted`; `weight_bits ≥ MatchConfig::proof_bits` (default `30`, §13.1) → `Proven`; `is_match` → `Consistent`; else `NonMatch`.
  - **Worked values.** Identical name + DOB + gender (+ phonetic bonus) is `≈ 28.97` bits → `Consistent`, deliberately short of proof: twins share all of it. Adding an identical address and email reaches `≈ 54.5` bits → `Proven` without any identifier.

All behaviour-defining numbers are pinned by agents/matching-algorithm.md and the test suite.
