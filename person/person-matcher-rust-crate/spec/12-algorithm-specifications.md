## 12. Algorithm Specifications

Full per-component score tables and pseudocode are in [agents/matching-algorithm.md](../agents/matching-algorithm.md) under "Detailed Algorithm Specifications". Summary:

- **§12.1 Deterministic** — fires on same-scheme identifier agreement (any of 42 schemes), passport-book agreement, or full demographic-tuple agreement (normalised given + family + DOB + compatible gender).
- **§12.2 Component scoring** — per-field scores in `[0.0, 1.0]` or `None`. Identifiers: exact canonical equality. Names: `name_algorithm` (JW / Lev / Exact / Combined) with nickname boost to `≥ 0.9` and `0.95 × given + 0.05 × middle` blend. DOB: exact (`1.0`) or same-year day/month transposition (`0.5`). Gender / blood type / multiple birth: exact equality, with gender `Unknown` scored as missing (`None`), since it means no gender was recorded; the name + DOB + gender short-circuit likewise treats `Unknown` as absent. Birth/death place: shared `score_named_place` (`0.7 × city + 0.3 × country`). Death date: reuses DOB transposition. Address: §12.4. Phone: E.164 preferred + legacy fallback. Email: canonical equality. Phonetic: Soundex. Relationships score as typed-set **Jaccard** over `(relation, person_id)` pairs (`|A ∩ B| / |A ∪ B|`), so a parent reference only agrees with a parent reference to the **same** person; tags score as set **Jaccard** over the case-insensitively normalised tag sets (`|A ∩ B| / |A ∪ B|`). Both are `None` (does not participate) when either side is empty (§23 T-33/T-34).
- **§12.3 Probabilistic** — `score = Σ(score × weight) / Σ(weight)` over participating fields. Phonetic bonus is asymmetric (`+ s × 0.05` when `s > 0.9`); only lifts.
- **§12.4 Address sub-score** — weighted average over postcode (0.5), city (0.3), line 1 (0.2). Line 1 is a `(house_number, street)` blend: `0.6 × street_sim + 0.4 × house_score` when both have a house number, street similarity alone otherwise. Empty-address fallback `0.5`. Best-of across `(current ∪ previous_addresses)` on both sides (FR-48).
- **§12.4a/b/c Place / date-of-death sub-scores** — see AGENTS for city / country blend rules.
- **§12.5 Confidence bands** — `score ≥ 0.90 → High`, `≥ 0.75 → Medium`, else `Low`; independent of `match_threshold`.
- **§12.6 Batch** — `match_one_to_many` (parallel-to-slice); `rank_one_to_many` (sorted descending; deterministic index tie-break). Engine is `Send + Sync`; consumers layer parallelism.
- **§12.7 Match evidence** — every `MatchResult` carries `evidence: Evidence` beside `score`, per the family contract [`agents/share/match-evidence.md`](../../../agents/share/match-evidence.md) (Fellegi–Sunter log-likelihood weights). `score`, `is_match` and `confidence` are unchanged by it. Code: `src/evidence.rs`.
  - **Weight.** Each non-identifier component that is `Some` adds `component_bits(s, m, u)`: `log2(m/u)` at `s ≥ 0.95`, `log2((1−m)/(1−u))` at `s ≤ 0.60`, linear between. A `None` component adds `0` and is not counted in `fields_compared`.
  - **`m`/`u` table** (informed estimates, not measurements): given name `0.95/0.01`; family name `0.92/0.005`; DOB `0.97/1e-4`; gender `0.98/0.5`; blood type `0.99/0.25`; multiple birth `0.98/0.5`; address `0.70/1e-4`; birth place `0.90/0.01`; death date `0.95/1e-4`; death place `0.90/0.01`; phone `0.60/1e-3`; email `0.70/1e-4`; relationships `0.60/0.10`; tags `0.50/0.20`. The phonetic score is **not** in the evidence: it is derived from the two name components, so per [`match-evidence.md`](../../../agents/share/match-evidence.md) §6 it is left out of the sum entirely (it still lifts `score`, §12.3).
  - **Identifiers** count as one field. A shared value under any of the 42 national schemes, or a shared passport `(country, number)` pair — the §12.1 identifier rules — adds `IDENTIFIER_BITS = log2(0.99/1e-12) ≈ 39.85` once. The §12.1 demographic tuple is **not** an identifier and adds no identifier bits.
  - **Contradictions.** Each national scheme under which both records parse a value (the scheme's own parser is the normalisation, so blank/invalid values are ignored) and the values differ is a `Contradiction { field: "identifier:<scheme>" }` (scheme = the `Person` field name, e.g. `identifier:us_ssn`) and adds `log2(0.01/(1−1e-12)) ≈ −6.64`. **Passports never contradict**: a passport number names a document, and a renewed book legitimately carries a new number.
  - **Strength**, checked in order: any contradiction → `Contradicted`; `weight_bits ≥ MatchConfig::proof_bits` (default `30`, §13.1) → `Proven`; `is_match` → `Consistent`; else `NonMatch`.
  - **Correlated groups** (public contract, `evidence::CORRELATED_GROUPS`; [`match-evidence.md`](../../../agents/share/match-evidence.md) §6). Within a group the present member with the largest absolute bits (ties to the larger value) counts in full and every other present member counts at `CORRELATED_DISCOUNT = 0.5`, for agreements and disagreements alike; the result does not depend on component order. Groups are disjoint:
    - `{address, phone}` — a household's address and landline are recorded together and move together; two people in one house agree on both for one reason, and a move makes both disagree for one reason.
    - `{death_date, death_place}` — both are determined by one fact, the death, and usually come from one certificate.
    - `birth_place` is **not** grouped with `address`: one is fixed at birth, the other is the current residence, so for different people they agree for different reasons; and `address` in two groups would be discounted twice.
  - **Value frequencies** ([`match-evidence.md`](../../../agents/share/match-evidence.md) §7). `MatchingEngine::match_persons_with_frequencies(a, b, &dyn ValueFrequencies)` takes a caller's frequency source; `match_persons` passes `NoFrequencies`, so plain calls use the table above. `score`, `is_match`, `confidence` and the breakdown are identical in both. `FREQUENCY_COMPONENTS` (public contract) = `given_name`, `family_name`, `date_of_birth`. When both records hold the **same key** under one of them and the component is a full agreement (`s ≥ 0.95`), its agreement weight is `frequency_bits(m, share) = log2(m / clamp(share, MIN_SHARE = 1e-9, m))` in place of `log2(m/u)`; a share at or above `m` gives `0`, never negative. Partial agreements and disagreements are never adjusted. **Keys** (public contract, `evidence::frequency_key(component, raw)`): `given_name` / `family_name` → `Normalizer::normalize_name(raw)` (the form name scoring compares; `None` if empty); `date_of_birth` → ISO 8601 `YYYY-MM-DD` (`raw` must parse as one). `FrequencyTable` (`new`, `insert(component, key, share)`, `from_counts(entries, total)` with share `count / total`) is provided. A placeholder such as `1900-01-01` with a share of `0.5` adds `≈ 0.96` bits instead of `≈ 13.24`.
  - **Terms** ([`match-evidence.md`](../../../agents/share/match-evidence.md) §8). `Evidence.components: Vec<ComponentBits>` lists every term — `"identifier"`, each `"contradiction:identifier:<scheme>"`, then each present component by name — with its bits after any discount or adjustment and `correlated` / `frequency_adjusted` flags. `weight_bits` is defined as their sum, so they add up exactly.
  - **Worked values** (defaults, no frequencies). Identical name + DOB + gender is `≈ 28.31` bits → `Consistent`, deliberately short of proof: twins share most of it. Adding an identical blood type (`+1.99`) gives `≈ 30.29` → `Proven`, just over the bar: twins do not share a given name, and the remaining risk, a common name, is what frequencies catch — with `family_name` at share `0.01` the same tuple is `≈ 29.29` → `Consistent`. Two people sharing only an address and landline give `12.77 + 0.5 × 9.23 ≈ 17.39` bits (undiscounted `≈ 22.0`), never `Proven`. Identical name + DOB + gender + address + email is `≈ 53.85` → `Proven` without any identifier.

All behaviour-defining numbers are pinned by agents/matching-algorithm.md and the test suite.
